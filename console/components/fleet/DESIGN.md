# 协作台 visual specification

The active design is the generated professional workstation concept at `outputs/verification/fleet-polish/concept.png` (outside this Sites source folder). Latest browser comparisons are desktop-preview.png, tablet-preview.png, and mobile-task.png in that verification folder. Example data exists only in browser test fixtures, never in the deployed application.

The shell uses a 188px device/project navigation rail, a 64px toolbar, a compact central workstation and task table, and an on-demand 410px reading inspector. Devices scale dynamically; project links use registered workspaces and their real controller/source conversations. At <=1100px the inspector becomes an overlay. At <=760px it becomes a full-screen reading drawer with a 58px header; main navigation moves to the bottom.

Tokens are centralized in app/fleet-professional.css: white surfaces, #f6f8fa canvas, #263142 ink, #657487 secondary text, #e3e8ed borders, #216d63 teal, #edf6f4 selection, #3779ca activity blue, 8px radius, 4/8/12/16/24 spacing. UI uses Segoe UI/Microsoft YaHei/system fallbacks: 13px controls, 13-14px reading, 18-20px page headings, 11-12px metadata. Outline icons are 15-20px with a restrained stroke. Controls have explicit focus, hover, selected and disabled states.

Navigation: 工作台 / 设备 / 任务 / 项目 / 流程 / 文件 / 成员. Mobile uses five thumb-accessible controls: 工作台 / 设备 / 派任务 / 任务 / 更多. Primary action: 派发任务. Home presents global scoped task statistics, running projects, a device table, six recent native tasks, and transfer details only when files exist. Full native and collaborative task histories use server pagination and filter-bound cursors. Reading is separate from task/project/flow creation forms.

State semantics are preserved: recent_activity is 最近活动, never an assertion that the desktop process is currently running. Old/unknown inventories remain awaiting sync; stale online state is not idle. Submitted output is awaiting result confirmation, not automatically accepted. Complete inventory means scanned AND all advertised rows received. Task statistics come from scope-wide backend aggregation, not the recent overview sample. Native inspector messages are public user/assistant content and tool summaries only.

Motion is purposeful: 220ms inspector entry, 180ms exit, 180ms hover/focus selection, smooth actual byte-progress updates. No synthetic task percent or persistent flashing. prefers-reduced-motion disables nonessential animation. Desktop inspector opening preserves scroll position and does not trap focus; narrow-screen drawers trap focus and restore it without scrolling. The panel does not remount on periodic data refresh.

Intentional concept deviations: omit nonfunctional checkboxes/ellipsis controls, show real directory coverage and archive state, support six pageable home rows rather than fabricated sample rows, render current files only when they exist, and keep task approval replies explicit. Native tasks do not expose a pretend desktop conversation control channel. Only collaborative task details offer supported manual replies/actions.

Visual and interaction evidence is stored outside the source project. The fidelity ledger records comparison points and remaining intentional differences; production connectivity and remote execution are independently validated by the deployment task.

2026-10-19 refinements: mobile dialogs occupy the visual viewport, preserve draft task fields across close/back within the current session, and hand off a single browser history entry between dialogs. Touch actions are at least 44px; form controls are 16px. The desktop does not reserve an empty reading panel. Native/collaboration filters never reuse another device or page snapshot.

Intentional differences from the latest concept: retain the existing monitor brand icon, live status wording, real device group/project navigation, node version and inventory indicators; omit decorative instructions in empty states. Mobile uses a second action line per device for readable task titles, full 44px actions, and settings access. No invented running tasks or percentages. Local visual fixtures are outside this repository and are not published.

Stability: deduplicated overview refresh, bounded read backoff, visibility-aware polling, online recovery, caller cancellation plus request timeout. Mutations are never retried automatically. Admin cleanup creates exact-ID presentation tombstones with a recoverable batch record; original execution data remains available. Cleanup revision invalidates scoped cached views and events. Active/uncertain tasks cannot be cleared.

Message reading defaults to newest first, with explicit chronological ordering and conversation/tool filters. The latest assistant reply starts expanded. Updates follow when already reading the newest content; otherwise an ID-based visual anchor preserves the visible message and an update count offers a return action. Synced counts describe the received window, not a claim that all historical message bodies are loaded. Public text supports safe emphasis and code, no HTML execution or remote media. Native refresh requests are locked while pending, and both reply composers support Ctrl/Command+Enter with IME protection.
