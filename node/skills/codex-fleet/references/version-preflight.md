# 多机自动化2.0版本核对

适用范围：用户每次新启动的多机自动化2.0业务流程。这是总控的派发规程；不能把写入本文件当成已经完成远端检查，也不能声称网页已经具有服务端强制拦截。

## 本轮基线

使用GitHub仓库 `https://github.com/zhoudebao6-art/software-case-batch` 的main完整提交SHA。读取同一提交的release-manifest.json，固定release、清单文件SHA256及全部条目。不同节点不得各自拉取不断变化的main。版本检查完成后到开始业务前如节点重启、技能入口变化、安装/升级或关键文件变化，重新核对该节点；同轮断点恢复不能盲目更新正在使用的技能。

## 各机回传

在单独的本轮证据目录返回JSON，至少包含：

- runId、nodeId、device、checkedAt、repository、commit、release；
- actualSkillRoot、proEntry、aliasEntry、entryVerified；
- manifestSha256、installedFiles（relative_path、实际sha256、实际size、matched）、mismatches；
- Fleet节点版本、桌面组件版本、实际共享连接状态和本轮需要的能力；
- 若更新过：backupPath、rollbackManifestPath、configPreserved、轻量入口检查的退出码。

仅检查发布文件和实际入口，保留每台电脑自己的配置、技能集合、Codex账号、工具安装路径、历史批次和交付。发布清单缺失、条目重复、不安全相对路径、缺失文件或大小/哈希不一致都不得通过。旧版本号相同但文件不同也不得通过。

## 调度与验收

检查任务本身可以用execute加本机既有权限以写出证据，但提示明确禁止制作业务案件；只读检查不带任何制作技能自动执行意图。任务使用稳定ID，网络不确定时查原任务，不以新ID重复安装。检查结果产物上传完成后，总控下载并与GitHub固定清单逐项核对，完成fleet_accept，再派业务任务。

在业务提示与流程记录写入基线SHA、已验收检查任务ID、参与节点ID和技能名。支持dependencies的派工必须依赖对应已验收检查任务。使用自动推进流程时，先在创建业务流程前完成全部版本核对，不能把“模型说已完成”作为步骤通过条件。

每台参与电脑在首个业务任务启动时再次快速核对SKILL.md与核心脚本哈希；与本轮证据不符立即暂停本任务并回报总控，不继续混合版本制作。前置检查通过仅证明版本和运行入口，不等于案件交付验收。

## 不兼容时

节点在线而Codex连接不可用属于执行器异常。桌面版本未激活须等待正常切换；已有业务工作不能被强行终止。检查失败报告具体设备、步骤和原因，不能统一称为排队。已确定的取消、权限拒绝、未知执行结果都必须尊重；不能用版本检查绕过它们。
