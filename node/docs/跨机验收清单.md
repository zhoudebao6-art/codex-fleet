# 两台或三台实体电脑首次验收

先记录总控机器名、私网 URL、各节点名称/设备 ID、Windows 用户、Codex 版本、统一项目 ID 与当地路径。不要记录登录令牌、邮箱或邀请令牌内容。总控和每台节点运行 Diagnose-Fleet.ps1，核对实际登录和当地技能。邀请每台单独创建。

1. 不同外网的节点执行 `tailscale ping 总控私网机器名`，记录直连或中继；访问 `https://总控名称:8447/health`，必须证书有效。再使用带节点凭据的 `fleet_nodes` 成功查询，健康页不能替代认证验证。
2. A 派给 B 一个隔离目录中的小任务，显式调用 B 的当地测试技能，生成带随机标记的小文件。检查执行节点、当地线程、任务 ID、输出内容与 SHA256，A 下载后验收。
3. B 再派给 A 或 C，用同样方法确认反向派工。分别在同一 Codex 账号和不同账号的实体电脑上测试；共享账号并发设为 1，应保持第二个任务排队。
4. 执行中追加 `fleet_message`，检查消息回执及实际采用情况；执行完成后 `fleet_continue`，确认复用了同一当地线程。跨机 `fleet_handoff` 应创建新线程并显式取得输入。
5. 同一任务 ID/同一事件重复传送，检查只执行一次。关闭总控服务期间排队新任务，恢复后检查送达；运行中断网、重启总控，检查结果补传；重启节点时执行中任务应为 uncertain，不能自动执行第二遍。
6. 使用真实 DOCX、ZIP、视频分别上传下载，比较原文件与下载文件 SHA256；中途断网后续传。再用当地工具打开验证格式。传输成功不代表已验证所有文件制作技能。
7. 使用测试 Git 仓库的已提交改动导出 bundle，下载后导入并创建整合 worktree。分别测试无冲突与冲突，确认主工作目录未被整合脚本改动，执行实际项目测试。未提交改动应被导出脚本拒绝。
8. 有浏览器/录屏需求的机器单独验证这些技能在 Fleet 启动的 App Server 内能否发现并调用。桌面插件的临时连接不一定能被 CLI 子进程复用；缺少能力时应 blocked/failed 并留证，不能自动替换成伪造产物。
9. 检查开机启动、用户锁屏/注销、主机睡眠唤醒、Tailscale 重新连网和账号到期状态。总控 SYSTEM 模式与节点用户模式分别验证。当前机器没有实施真实重启或断电测试。

每一步保留实际任务 ID、事件、哈希和检查结果。只有全部所需场景通过后，才能把相应业务工作流作为已验收的跨机服务使用。
