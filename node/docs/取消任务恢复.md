# 取消任务恢复（0.3.11）

连接中断后，原任务可能进入 uncertain；点击取消会先变为 cancel_requested。节点、升级器和桌面联动入口会核对同一设备、任务与执行尝试，再确认原会话停止。

已连接的桌面共享执行器可确认该 Fleet 会话空闲。共享连接不可用时，恢复器先在独立临时目录验证本机 Codex 的写锁，再尝试以原模型、目录和权限挂接原空闲会话。不发送业务消息、不开始新的业务轮次、不关闭其他 Codex。

真实停止核验与本地取消结果、待发送回执在同一数据库事务保存。断网后由原有持久队列补报；重复处理不重复生成完成记录。升级器会等待回执发送完毕，联动入口也会短暂等待同步。

原会话仍被另一个进程持有、来源不匹配或网络检查失败时，不伪造停止结果。节点数据目录中的 metadata/cancelRecovery:<任务编号> 保存原因和下次重试时间。原生对话的未知状态仍保留给其原执行器处理。

此机制确认的是 Codex 会话状态；用户另行启动的服务和业务进程不属于取消动作，不会被强制结束。

网站操作员已手动结束的“不确定”任务，也需要核实原会话停止后才清理本地残留。恢复器保留操作员的原始结束记录，不重新上传完成事件，不把失败改成成功。
