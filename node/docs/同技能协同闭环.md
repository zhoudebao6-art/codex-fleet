# 同技能协同闭环

## 先运行 PC-01 与 PC-03

PC-01 是唯一跨机主控：冻结材料和 GitHub 提交、分工、核验、汇总。每个自动化分别绑定各机已有总控对话和项目。PC-03 的本地总控复用自己的登录、技能、依赖和工作路径，创建可在桌面查看的制作子任务。PC-02 暂不参与。

新批次拥有固定版本、输入哈希、原总控绑定和恢复规则。已经启动的批次不因配置或 GitHub 变更而偷换版本。设备不能仅凭“装有同名技能”就获派制作任务，必须通过真实发布文件核对。

分工按已接单任务、待派发保留项和可用执行槽选择电脑。同一类任务默认每机最多两件并行，其他业务占用容量时减少派发。尚未分配的材料随空闲容量补入，已执行的材料保持原编号和工作目录。多个小任务仍可并行，不按整台电脑单线排队。

## 自动恢复

1. 明确终止且可返修的失败，使用固定返修编号接续原成果，最多采用批次允许的次数。
2. 断线、超时、取消尚未确认属于状态待核实。保留原执行，只查询和恢复连接，不跨机重复执行。
3. 单项异常创建持久排障记录，并直接交给 PC-01 的对应原总控。其他材料继续。
4. 主控使用 `scripts/Report-DeliveryRecovery.mjs` 回报诊断。服务端复核原任务终止、权限、返修限额和是否已有下一次尝试。
5. 原任务恢复时自动关闭排障项。无回报、核心材料缺失、权限受限、恢复次数耗尽会保留明确的待处理项，不无限重试或假报成功。
6. 大文件按原下载偏移续传并校验 SHA256。某项失败独立退避，不阻塞其他批次的已完成文件。
7. 只有所有成果经过收据核验并真实收齐到 PC-01，整批才标为已交付。
8. 桌面桥接每 15 秒进行独立健康检查，异常节点暂停接新任务。原任务不被取消或转派；主控的联网、核验和收集仍可工作。
9. 完成通知丢失时，每 30 秒通过只读接口检查同一会话、同一轮次的正式结束记录。只有精确结束证据才能补回状态；重启后同样恢复原文件上传，仍需网站收据校验。读取记录不会抢占会话写入权。

## 技能改进与发布

故障记录、主控诊断和 learning 记录持久保存，后续同技能的版本准备任务会读取最近的记录。记录是排障线索，不能替代实际验证或发布收据。

总控应执行：复现失败 → 独立候选副本 → 修复 → 原失败样例与正常样例回归 → 独立审核 → GitHub 发布 → 一台空闲设备试用 → 其余空闲设备同步 → 下一批重新冻结版本。运行中和含未发布本地修改的技能不得被覆盖。

0.3.22 将候选修复、另一设备独立审核、GitHub 发布、分控试用和主控同步保存为网站上的五阶段任务。主控节点按原有周期自动推进，无需保持某个总控对话一直运行。原总控明确未发出的派工或已结束却遗漏的派工，可用原编号补偿；执行不确定时保留原任务并核查。

每种技能登记冻结执行器与独立审核设备，开启按需自动维护；普通交付和版本核对不生成维护或演练。停止演练不关闭自动维护，已完成演练也不能自动更改发布策略。每个真实问题独立通过复现、回归和审核。正式发布只允许在固定基线上非强制快进，分控与主控核验同一提交和文件树后才允许剩余材料按新批次接续。旧批次、已通过成果和在用版本均保留。阶段失败有限重试，断线后沿用固定编号和已上传文件；没有真实审核、远端提交或同步收据就不会标为成功。

网站“自动交付 → 技能维护”展示五阶段的设备、任务、错误与提交，可暂停后续步骤。硬件故障、账号失效、必要权限和原材料缺失仍可能需要人介入。自动化不能把未确认的执行当作失败重复制作，也不能靠模型说明替代实际文件和审核证据。

## 重开桌面与启动恢复

已配置联动的电脑重复打开“Codex Fleet 联动”时复用共享连接，不暂停接单、不关闭或重启已有节点。PowerShell 7 调用自动转交 Windows PowerShell 的 Appx 启动接口。只有首次切换执行器连接方式才要求原任务安全结束。

启动记录丢失或过期时，启动器核对 worker.lock 的 PID、进程创建时间、程序、脚本与配置路径，确认同一实例后恢复记录；不会仅凭进程名接管其他实例。工具启动的临时 app-server、远程 CLI 不登记为桌面桥接。桥接补丁在正常重开桌面后生效，不热替换运行中的会话。

## 新设备如何加入

1. 安装接入包，保留账号、MCP、技能、节点身份和防休眠设置。
2. 自动上报可用项目、技能、版本、桌面连接和容量。未完成验证先不接业务。
3. 总控按自动化类型挑选其已有原总控，使用短流程证明“原对话收到任务、子任务执行、读取技能、文件回传”，然后绑定。
4. 与现有设备共用同一技能发布基线；机器路径与本地配置独立。
5. 先一件轻量试单，通过后加入容量分配。不同类型工作的上下游关系由用户说明后单独建模，不自行推断。

暂时掉线不会抹去编组、历史成果与任务状态。重新上线后原编号续接；未知执行不会自动迁移到另一台电脑。

## 本轮真实验证与边界

固定批次 `same-skill-loop-20261021-01` 使用 PC-01 与 PC-03 核对相同的 software-system-delivery 发布版本，再通过 PC-03 原总控派出两个极小探针，本机汇总回传文件。不重新制作完整业务案件。

本机本轮遇到桌面桥接无响应，已通过原会话正式结束记录恢复预检回执；这不是重跑任务或手工填通过状态。本轮将制作工作留给健康的 PC-03。本机桌面桥接的新异步管道修复需要在正常退出并重新打开 Codex 后加载，不能把磁盘补丁当成运行中的桥接已修好。后台完成补偿已热更新至 Fleet 节点，不中断 Codex 工作。


## 维护触发与交付分开
维护由具体质量差距、缺陷、升级或人工需求触发，先由主控判断；普通交付和版本核对不自动修改技能。网页可填写问题、预期效果和关联批次，记录原因、判断回执、候选、独立审核、发布和各机版本。需要时先固化独立验收脚本，再修复候选；不允许改测试以降低标准。执行失败与质量不达标分别处理，运行故障不进入技能发布。

旧批次绑定旧版本，不因新维护重启或替换。自动失败恢复仍使用同一事务和文件身份；未知状态保留、核实，不盲目重跑。新设备包包含提交维护请求的入口和相同协同规范。
