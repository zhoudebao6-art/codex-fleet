# 桌面启动器签名与受控设备接入

PC-05 的已核验故障是 Windows CodeIntegrity 3077 拦截未签名的 `codex-fleet-desktop.exe`，策略名为 `VerifiedAndReputableDesktop`。同一文件哈希与拦截日志一致。关闭并重开 Codex 不能修复签名问题。

0.3.24 普通安装包包含通用检测与节点稳定性修复，不包含正式签名启动器。它能继续安装/更新普通 Fleet 节点，但不能据此宣称 PC-05 桌面联动已打通。新装和升级均记录 `desktop-bridge/trust-status.json`；桌面信任问题不应阻止原节点启动。

## 接入行为

- 安装与首次联动启动会在要求关闭 Codex、暂停领取任务之前检查签名要求。
- Windows 已开启对应应用控制且没有有效签名时，停止桌面准备，保留原 Codex、节点身份、技能和节点服务。网页能够读取 `launch-status.json` 中的 `DESKTOP_TRUST_REQUIRED`。
- 既有已连接桌面重开仍使用原先共享连接，不因本轮预检中断其工作。
- 有正式签名发布目录时，先核对清单、源文件 SHA256、二进制 SHA256、有效 Authenticode 签名与发布者指纹，再安装。相同二进制直接复用。没有正式替代版本时不重编译覆盖已签名文件。
- 未启用该签名要求的现有设备可继续本地构建，构建结果与源哈希均记录，后续相同版本复用。
- “签名有效”不等于所有组织策略均放行。目标设备必须完成实际启动和桌面可见测试后才能投入生产；禁止通过关闭策略、换名、移动目录或换壳绕过应用控制。

## 发布方准备

需要已有、具备私钥且符合目标电脑信任要求的代码签名证书，以及该证书发布者提供的时间戳服务。当前主控未发现这样的证书，所以不能声称已经生成可在 PC-05 运行的正式签名包。

没有管理员权限也不应反复重装或重开。最短正规路径是由发布方取得受信任 CA 颁发的代码签名证书，用硬件令牌或云 HSM 保管私钥，签名这两个发布文件，再发送同一份签名安装包给所有设备。微软的 Smart App Control 指南要求有效、受信任发布者签名；单纯自签名不等于获得系统信任。[微软签名要求](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control)

Azure Artifact Signing 有地区资格限制：目前组织面向美国、加拿大、欧盟和英国，个人面向美国和加拿大；中国境内使用者不能直接假定可注册。可向提供当地身份审核服务的正规 CA 确认代码签名资格，再选择受支持的签名工具。费用、身份审核与采购由发布方决定，本项目不会自动购买证书或导入信任根。[微软代码签名方案与地区说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)

由持有证书的发布机器执行：

```powershell
& .\scripts\Build-SignedDesktopLaunchers.ps1 -CertificateThumbprint '<已有代码签名证书指纹>' -TimestampServer '<证书发布者的时间戳地址>'
& .\scripts\Build-Package.ps1 -RequireSignedDesktop -OutputDirectory '<新的发布目录>'
```

签名脚本不安装证书、不修改信任和应用控制策略；已有发布目录不会被覆盖。产物位于 `scripts/desktop-binaries/win-x64`，安装包会包含两份已签名启动器和校验清单。更改 C# 源码后必须重新发布匹配的签名文件。

上述脚本适用于已安装到证书存储、签名 API 可以访问私钥的证书。若供应商要求专用云签名服务或命令行工具，应先接入其正式发布流程，再生成同格式校验清单；目前未实际配置或验证任何供应商的证书。`-RequireSignedDesktop` 缺少正式发布文件时会在出包前停止。

如果 PC-05 由组织管理，需由其软件发布/安全维护方确认获准发布者或提供正式允许的签名包；本项目不会代为批准或扩大信任。

## 验收

1. 核对正式发布包校验信息，按原目录升级；正在运行时保持原任务，等待安全空闲后切换。
2. 通过受支持的 `Prepare-DesktopBridge.ps1` 准备入口，确认 `preparation-status.json` 成功。
3. 正常退出后从“Codex Fleet 联动”启动，确认 `launch-status.json` 成功、共享执行器心跳就绪。
4. 派发一个短对话，核验桌面显示和小文件回传。只有此验收完成，才启用区域总控生产派发。

上述 1–4 尚未在 PC-05 完成；此次源代码回归测试不能替代真实签名发布与目标机器验收。
