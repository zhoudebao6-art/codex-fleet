# Codex Fleet 0.3.24 部署指南

0.3.24 包含桌面启动信任预检与节点恢复修复。新装会自动准备“Codex Fleet 联动”入口；已接入电脑原目录升级。若 Windows 应用控制要求正式签名，普通安装包会保留节点接入并记录桌面未就绪原因，不能据此宣称桌面联动成功。持有正式签名启动器后，桌面共享执行才通过正常退出原 Codex、从联动入口重新打开完成验证，具体见《桌面启动器签名与受控设备接入.md》。

本版默认接入 Sites 网站总控。各台电脑主动连接网站，保留本机 Codex 登录、技能、其他 MCP 和项目；同一个 Codex 账号可以用于多台设备，设备身份各自独立。无需安装本地 Hub、配置 Tailscale 或开放入站端口。

## 默认同步全部工作空间

新装与保留原配置的升级，默认启用工作空间自动接入。节点通过 Codex 官方项目接口读取全部本机有效项目根目录，并合并本地会话记录和已有 Fleet 配置目录，约每分钟更新。未创建对话的已登记项目也会出现，不需要逐个点击“使用此项目”。同一路径去重，网页修改过的项目名、总控会话和自动化设置保留。

节点上报 `capabilities.workspaceCatalog`：`synced` 已同步，`partial` 表示 Codex 项目接口不可用但已有任务目录仍可用，`retrying` 表示等待网络恢复。旧版 Codex 不支持项目接口时不能声称无对话项目已完整接入；需升级本机 Codex 后复核。不存在的历史目录跳过，已接入目录失效会显示需要处理，派任务前还会重新核对本机来源。

此功能不扫描整块磁盘，不修改 Codex 登录、原权限和技能，不自动发起任务。网站仍按用户角色和设备分组控制访问；本机原项目设置继续生效。显式配置 `workspaceAutoImport: false` 可以保留手动接入方式，升级不覆盖这一选择。

## 安装前

1. 在网站“设备 → 添加电脑”为这台电脑生成独立邀请，下载完整 `codex-fleet-0.3.24-windows-x64.zip` 和对应的 `*.invite.json`。不要使用 source ZIP 安装；不要把另一台电脑的 config/data 当安装包。
2. 使用平时运行 Codex 的同一个 Windows 用户。Codex 须已安装并在本机登录；安装器不会复制或更换登录。如果自动找不到 codex.exe，可显式指定 `-CodexPath`。
3. 确认 D 盘可用且 `D:\codex+` 可写。本版缓存、临时文件和备份固定使用该目录；没有 D 盘会在安装改动前停止，不会自动使用 C 盘。安装目录默认 `D:\CodexFleet`；已安装电脑必须使用查明的原目录。
4. 对照网站发布的 SHA256 校验 ZIP，匹配后解压到 `D:\codex+\temp` 下的独立目录。不要直接在压缩包内执行，也不要将解压目录作为安装目录。包内 manifest 会再次校验文件与版本。

在执行安装前，仅给当前 PowerShell 进程设置缓存位置：

```powershell
$env:TEMP = 'D:\codex+\temp'
$env:TMP = $env:TEMP
$env:TMPDIR = $env:TEMP
$env:PSModuleAnalysisCachePath = 'D:\codex+\cache\powershell\ModuleAnalysisCache'
Get-FileHash -LiteralPath 'D:\接入\codex-fleet-0.3.24-windows-x64.zip' -Algorithm SHA256
```

## 全新电脑

将以下示例路径换为已经核实的绝对路径。显式传 `-Invitation` 会直接读取邀请，不弹文件选择框；命令不会自动打开浏览器。

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File 'D:\codex+\temp\本次解压\codex-fleet-0.3.24-windows-x64\Install-Sites.ps1' -Invitation 'D:\接入\PC-04.invite.json' -InstallDir 'D:\CodexFleet'
```

默认建立 `workspace` 项目映射和 `D:\CodexFleet\workspace` 工作目录。如要映射已有目录，添加 `-ProjectId workspace -ProjectRoot 'E:\已有项目'`，该目录必须真实存在且在这台电脑上。新设备安装只增加 Fleet 技能和同名 MCP；其他技能、MCP 和登录不变。

启动方式优先保留已匹配的原配置。若 Windows 拒绝创建计划任务，使用当前用户“启动”文件夹中的隐藏快捷方式。两种方式都失败时会明确提示，仍尝试启动本次节点进程；这时“当前已启动”不代表“下次登录会自动启动”。不会为此提升权限或更换 Windows 用户。

## 已有 pending / enrolling 节点

保留原目录和节点身份。已是本版、仅等待邀请的电脑可执行：

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File 'D:\CodexFleet\app\scripts\Complete-Enrollment.ps1' -InstallDir 'D:\CodexFleet' -Invitation 'D:\接入\PC-04.invite.json'
```

旧版 pending 节点可使用上面的 `Install-Sites.ps1`，指定原安装目录；先验证包，再停止并接入。原节点 ID、登录、其他技能和项目权限映射保留。接入断线后使用原邀请重试；不要删除 config、生成另一节点 ID 或换新邀请。安装失败状态写入 `config\installation-node.json`，记录实际阶段。

如果失败发生在 `local-integration` 或之后，先查节点是否已 enrolled。网站可能已经消费邀请；此时不要再次接入，也不得恢复旧凭据覆盖已生效的新绑定。`Update-Fleet.ps1` 负责程序升级，不会重新添加缺失的 MCP 或注册启动项。

让本机 Codex 按 `installation-node.json` 记录的失败阶段逐项修复：

- Fleet 技能：检查当前用户 `CODEX_HOME\skills\codex-fleet`，缺失时从原安装目录 `app\skills\codex-fleet` 复制；保留其他技能。存在同名自定义技能时先备份。
- Fleet MCP：在本机内存中检查 `codex mcp list --json`，不要转发整个输出。仅在没有 `codex_fleet` 条目时执行下面的添加命令；若已有条目指向其他安装，保留并查明原目录，不能覆盖。
- 自启：调用已安装的启动注册助手，它会检查既有机制并去重。若返回 `enabled=false`，先处理明确原因；当前节点能运行不等于自启已配置。

```powershell
# 仅确认 codex_fleet 条目缺失时执行；codex.exe 使用原有已登录程序。
codex.exe mcp add codex_fleet -- 'D:\CodexFleet\runtime\node.exe' 'D:\CodexFleet\app\src\mcp.mjs' --config 'D:\CodexFleet\config\node.json'

# 恢复当前用户登录启动；只读检查失败时不会盲目添加第二个入口。
. 'D:\CodexFleet\app\scripts\Windows-Common.ps1'
. 'D:\CodexFleet\app\scripts\Windows-Startup.ps1'
Register-FleetStartup 'D:\CodexFleet' 'Node' | ConvertTo-Json

# 恢复本次进程，再核验最新心跳。
& 'D:\CodexFleet\app\scripts\Start-Fleet.ps1' -InstallDir 'D:\CodexFleet' -Role Node
```

## 已 enrolled 的同站点电脑

不需要新邀请。`Install-Sites.ps1` 会明确拒绝重新接入并提示使用升级器；新邀请代号不一致时也会拒绝，防止把旧电脑当成新设备。

优先在网站设备详情发起升级。需要本机命令时，使用完整 ZIP、网站 SHA256 和原目录：

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File 'D:\codex+\temp\本次解压\codex-fleet-0.3.24-windows-x64\scripts\Update-Fleet.ps1' -PackagePath 'D:\接入\codex-fleet-0.3.24-windows-x64.zip' -Sha256 '<网站发布的64位SHA256>' -ExpectedVersion '0.3.24' -InstallDir 'D:\CodexFleet' -Queue
```

升级器验证后排队，等待当前任务、传输和待发送事件结束；只正常停止本安装的节点，保留身份、队列、登录和其他技能，失败后恢复。返回排队状态不等于升级完成，需要继续检查设备版本及最新心跳。升级不要求关闭其他 Codex，也不使用模型执行任意安装指令。

## 已绑定其他站点

停止接入，保留原安装、身份和配置。安装器不会消费当前邀请、停止旧节点或覆盖站点绑定。站点迁移需要单独确定迁移方案，不能用新邀请强行覆盖。

## 验证接入和自启

用已安装的工具导出不含令牌、提示正文或登录数据的诊断：

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File 'D:\CodexFleet\app\scripts\Export-Diagnostics.ps1' -InstallDir 'D:\CodexFleet' -OutputFile 'D:\codex+\temp\fleet-diagnostics.json'
```

应确认 `version=0.3.24`、`enrollmentState=enrolled`、`connection.online=true`、最近同步时间更新、`codex.ready=true`。再从网站确认该设备独立代号和新鲜心跳；仅看到进程或安装成功文字不算接入验收。

`config\installed-node.json` 的 `startup`、`startupMethod` 记录实际注册结果。当前进程启动成功不能证明下次登录触发成功；在用户下次正常登录时复查心跳，不为测试强行注销或重启。

新开本机 Codex 聊天可加载新增 `codex-fleet` 技能/MCP；调用 `fleet_nodes` 确认与网站台账一致。桌面“Codex Fleet Console”快捷方式用于本机免密进入协作台；普通未登记设备使用网站账号登录。安装无需先打开控制台。

运行问题可使用 `app\scripts\Diagnose-Fleet.ps1` 本地查看；需要交给其他人时优先分享经过检查的 `Export-Diagnostics.ps1` 输出，不发送整个 config、auth.json、浏览器 Cookie 或完整 Codex 日志。

## 使用和历史说明

网站中可选择设备、查看任务与公开进展、传输文件和发起自动流程。提交与执行、执行完成与验收分别显示；断线和不确定状态不会被当作成功。

原生对话续接的占用与权限边界见 [原生对话续接说明](原生对话续接-0.3.3.md)。0.3.4 仅调整隔离能力探针，使模型网络临时不可达不会被误判为没有写锁；0.3.5 只修安装与启动流程，未改变原生会话权限或执行策略。

详细 Sites 功能历史见 [Sites 操作说明](Sites-0.3.0-操作指南.md)。需要继续维护既有自建 Hub/Tailscale 环境时，另读 [旧版私网部署指南](旧版私网部署指南.md)；其中旧版安装步骤不适用于本次 Sites 新电脑接入。
0.3.24 改进恢复：正常停止会立即取消后台查询，并记录退出阶段。升级或联动切换等待超时后，仅在进程身份、停止意图、本地队列及网站在途任务均核验通过时，备份数据库并结束卡住的空闲 Fleet 节点；不结束 Codex 桌面或其他项目。无法核验时保留进程并明确报错。启动使用互斥锁，避免恢复程序与手动启动生成重复节点。maxTaskMs 在下一项任务开始时生效，正在执行的任务保持原时限。

旧节点已经离线且卡在停止阶段时，从校验过的新包运行 scripts\Repair-FleetNode.ps1 -InstallDir D:\CodexFleet。此操作只恢复节点，随后按原目录升级；原有配置、历史任务、登录和技能保留。不要删除 stop.request 来绕过核验，也不要批量结束 node.exe/Codex。具体操作见《节点停止恢复.md》。

0.3.24 会对连接中断后的已取消协作任务自动核对原会话；确认停止后持久记录结果并同步，解除对升级和联动切换的阻挡。不能核验时保留原状态，详见《取消任务恢复.md》。
