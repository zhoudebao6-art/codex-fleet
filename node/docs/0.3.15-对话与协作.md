# 0.3.15 对话、协作与新设备

- 新建对话：选择电脑和项目，原文发给桌面 Codex，使用项目实际目录，不加协作工单提示或 Fleet 标题。
- 原对话发送：保持原 threadId、模型及权限；正在运行时追加消息，保留原执行者与审批通道，不中断原任务。
- 协作任务：独立任务并发，默认每设备 4 项，网页设备资料可调 1–16。明确依赖、同名输出冲突、设备离线或额度限制会显示等待原因。
- 多机流程：声明各机输入、输出与最终汇总步骤。服务端持续推进，全部前置文件完整上传后才派汇总任务；未完成子任务不能确认整批完成。
- 文件交接保留目标工作空间、执行方式、预期输出。不可把上传成功、排队、对话创建等同于制作完成。

安装包包含防休眠与唤醒组件。新安装、已接入节点启动时自动启动电源助手；交流电保持受控设备可用，电池策略和手动休眠保持明确边界。自动检查网卡、局域网中继及系统能力，不承诺不支持的硬件可被唤醒。异地唤醒需要目标局域网内一台在线中继。

已有节点通过网页升级本包，保留身份、登录、技能和队列。更新文件不代表已运行的桌面进程加载了新桥接代码；网页 `conversationDispatch` 只有新桥接握手成功才为 true。正在工作时不关闭 Codex，待用户正常结束后从“Codex Fleet 联动”打开；本版不会偷偷改用后台执行器。

此次仅做隔离回归和接口/UI核验，不重新运行先前整批制作。真实桌面显示及联网稳定性须以设备运行新版后的证据为准。
