# 原生对话续接

网站的电脑任务详情可以向对应电脑已有的 Codex 对话发送消息。节点版本需为 0.3.3，并通过本机能力检查。成功发送后仍是原来的对话 ID、目录和历史，不新建替代对话，也不自动打开或关闭电脑上的窗口。

## 结果

- 已续接：Codex 已返回原会话的新一轮 ID。任务完成状态和公开回复继续同步到网站。
- 被占用：该会话正在运行，或仍被另一 Codex 进程加载。Fleet 不抢占、不中断；请先在原电脑释放占用，再明确重新发送。
- 不支持：本机未通过写锁检查，原目录或会话来源改变，或原权限不能完整恢复。不会自动改用新会话或更宽权限。
- 结果待核实：发送前的持久记录已保存，但连接中断或进程退出导致结果无法确定。不会自动重发；先查看原会话确认。

## 保留范围

发送前同时核对本机目录、已同步任务来源和当前派发批次。原会话的模型、审批策略和沙箱必须能够逐项恢复。当前支持明确保存的普通沙箱策略，以及可证明等价的标准只读或完全访问配置；复杂自定义权限配置暂不支持。没有历史权限记录的空会话也暂不支持。

权限读取仅处理 Codex 官方返回、位于本机 Codex 会话目录内的历史文件，从中抽取必要的 `turn_context` 权限字段。不上传推理、开发者指令、命令原文或整份日志。取得官方写锁前后再次核对权限，发现变化即停止发送。

## 去重与设备检查

网站使用固定请求 ID；重试同一次请求不会新增任务。节点在发出消息前先保存发送意图，重启后保留；不确定的发送不会自动重做。

节点启动时使用独立临时 Codex 配置和本地模拟模型验证真实跨进程写锁。检查不使用用户登录、不调用外部推理、不操作业务会话。只有成功验证“正在运行时拒绝、已加载但空闲时仍拒绝、释放后同 ID 接续”的电脑才开放入口。检测到 Codex 可执行文件改变后，需要重新启动节点完成检查。

任务可通过官方 `codex://threads/<id>` 入口定位。已保存并可读取的原会话，不等于已验证桌面侧栏自动刷新；Fleet 不修改 Codex 内部全局状态来强制显示。

## 升级恢复

0.3.3 修复旧节点停机等待与升级器超时不一致的问题。收到停止请求时，节点会立即唤醒轮询等待，停止新的请求和派发，关闭自己的只读目录采集进程。升级器使用已验证新包中的停止工具，给旧版节点保留 180 秒正常退出时间。

升级时另有临时恢复守护，最多观察一小时。它只识别本次升级进程及本安装的节点进程，核对 PID、创建时间、程序路径和配置；不会强制结束它们。升级进程意外退出后，守护等待旧节点自然结束，在升级锁空闲时恢复节点；目录替换中断时仅恢复本安装记录的旧应用目录。恢复记录保存在节点数据目录的 `upgrades/recovery-*.json.result.json`。
