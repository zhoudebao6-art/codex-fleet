# Codex Fleet 0.1.1：Windows 多机协作

总控放在另一台较常在线的 Windows 电脑；各工作电脑运行节点适配器。每台保留自己的 Codex、登录、技能、MCP 和项目工具。设备使用独立随机 ID，同账号不会把两台电脑合成一台。无须租服务器，但 Codex 推理和 Tailscale 组网仍需要其官方在线服务。

## 安装顺序

1. 把完整 Windows ZIP 解压到一个独立目录，例如 `D:\FleetPackage`。不要直接在压缩包里运行。包内含 Node.js 22.23.2 x64、Tailscale 1.104.1 签名 MSI、源文件和 SHA256 清单；已有 Tailscale 会保留。Windows ARM64 未验证。
2. 在常在线电脑上，以管理员身份运行 `Setup-Hub.cmd`。安装位置默认 `D:\CodexFleet`，与解压目录分开。首次安装 Tailscale 网络驱动时 Windows 会显示管理员授权；登录你的 Tailscale 网络。MagicDNS 和 HTTPS 证书功能须在其管理控制台启用。脚本会提示实际缺项。
3. 总控仅监听 `127.0.0.1:43127`。Tailscale Serve 将它发布为私网 `https://机器名.网络名.ts.net:8447`。不需要公网 IP、路由器端口转发、Funnel 或开放公网 App Server。已有其他 Serve 路由不会被重置。
4. 在总控 PowerShell 创建每台电脑各自的邀请：

```powershell
& D:\CodexFleet\app\scripts\New-NodeInvitation.ps1 -InstallDir D:\CodexFleet -Name pc-a -Projects workspace -AccountGroup account-family-1
& D:\CodexFleet\app\scripts\New-NodeInvitation.ps1 -InstallDir D:\CodexFleet -Name pc-b -Projects workspace -AccountGroup account-family-1
```

邀请默认 24 小时有效、一次使用。只把对应的 `*.invite.json` 交给该电脑使用者。安装包本身没有总控口令、节点口令或 Codex 凭据。重试失败安装会保留同一个节点身份，不能把已接入电脑的整个 config/data 文件夹复制为另一台节点。

5. 各工作电脑使用原本运行 Codex 的 Windows 用户登录；确认其 Codex 本身能完成一个本地任务。运行 `Setup-Node.cmd`，登录同一 Tailscale 私网（Tailscale 身份与 Codex 账号没有绑定关系），提供邀请文件、统一项目编号及当地项目路径。例如两边都叫 `workspace`，当地路径可以分别是 `E:\项目甲`、`D:\工作\项目甲`。
6. 新开一个本地 Codex 聊天，使用 `$codex-fleet` 并让它调用 `fleet_nodes`。节点应显示独立设备 ID、最近心跳、项目及当地技能。现有聊天可能需要重开才能加载新增 MCP。安装只新增 `codex_fleet` MCP 和 `codex-fleet` 技能；已有同名技能、config.toml 会先备份到 `D:\codex+\backups`。

无图形向导的安装入口为 `Install.ps1 -Role Hub/Node`。详见脚本参数；`-NoStartup -NoMcp -NoStart` 用于受控测试。节点安装只使用本机现有 codex.exe；不会下载另一个 Codex、复制 auth.json 或替换用户技能。

## 总控尚未安装时，先准备工作电脑

在工作电脑上解压完整安装包后，用原有 Codex 所属的 Windows 用户运行：

```powershell
& .\Install.ps1 -Role Node -InstallDir D:\CodexFleet -PrepareOnly
```

也可以运行 `Setup-Node.cmd`，邀请文件路径留空。此模式安装节点、协作技能、MCP 和登录启动项，生成独立设备身份，检测本机 Codex 登录与技能；不创建总控，也不提交任务。默认项目编号 `workspace`，默认工作目录 `D:\CodexFleet\workspace`。需要使用既有项目时，在安装命令中指定 `-ProjectId` 和 `-ProjectRoot`。

`fleet_local` 返回 `enrollmentState: pending` 和 `connection.state: awaiting_enrollment` 属于正常待接入状态，不等于已经实现跨机协作。总控安装后，应给该节点生成允许相同项目编号的独立邀请；把邀请交给该电脑后运行：

```powershell
& D:\CodexFleet\app\scripts\Complete-Enrollment.ps1 -Invitation 'D:\接入\本机.invite.json'
```

脚本暂停节点、绑定邀请并重新启动，保留设备 ID、现有登录、技能和项目目录。若中途断线，重试同一命令；`enrolling` 表示等待确认，不能换用另一总控的邀请。不要复制 config/data 作为另一台新电脑。已加载的 Fleet MCP 会在下次调用时读取接入状态；首次安装 MCP 后仍需要新开聊天。

## 异地联网和常在线运行

所有电脑必须属于可以互访的同一 tailnet；不同 Tailscale 登录用户可由私网管理员邀请加入。推荐 Tailscale 访问规则只允许工作节点访问总控的 TCP 8447。不要把所有成员授予整台机器的任意端口访问。节点主动向总控发起 HTTPS 请求，各节点之间无需入站端口。总控仍校验独立节点口令与项目权限。

Tailscale 优先尝试直连，受 NAT/网络限制时可使用其中继。这是现有官方服务，无需自己租机器，但不能保证任何单位网络都允许连接。若官方登录或中继被所在网络阻断，需要当地网络管理员放行，不能由安装包绕过。

在总控执行下列命令可保留注销后的组网连接（需管理员权限）：

```powershell
& D:\CodexFleet\app\scripts\Enable-PrivateNetwork.ps1 -InstallDir D:\CodexFleet -Role Hub -Unattended
```

管理员安装的总控注册开机 SYSTEM 任务；它只运行队列服务，不运行 Codex。非管理员安装退为用户登录启动，并显示提示。节点始终在原 Windows 用户登录后启动，以保留其登录和工具环境。锁屏通常可继续 CLI 工作；注销会中断用户执行环境。浏览器、录屏、桌面技能是否可用取决于当地会话及工具，第一版未证明其无人值守兼容性。电脑睡眠期间不能提供服务；请由设备所有者配置常在线电源策略。

总控管理入口：

```powershell
& D:\CodexFleet\app\scripts\Console-Fleet.ps1 -InstallDir D:\CodexFleet
```

如果总控本身也要作为一个 Codex 工作节点，停止已有总控后，在同一安装目录再安装 Node 角色；两个角色配置互相独立，安装后分别启动。总控管理台能直接提交任务，不要求总控电脑登录 Codex。

## 派工、消息、交接和结果

示例提示词：

> 使用 codex-fleet，先列出设备和 workspace 项目的技能。把已授权的文档处理交给 pc-b，显式指定它当地安装的技能，写清输入如何取得、产物相对路径和验收标准。保留任务 ID，检查真实产物后验收；遇到 blocked 或 uncertain 报告原因，不自动换账号重跑。

`fleet_assign` 提交任务，`fleet_message` 补充正在执行的指令，`fleet_continue` 在原 Fleet 会话继续，`fleet_handoff` 在另一台创建接续任务，`fleet_download` 下载经哈希校验的产物，`fleet_summary` 汇总最近 500 个可见任务。下载写到调用方配置项目的相对路径，不覆盖已存在文件。大于 512 MiB 的单文件默认拒绝；上限可在可信管理员配置中调整。

任务必须声明当地相对 `outputs`，否则只回传文字报告。Word、ZIP、视频等作为不透明二进制文件按块传输，系统不自动生成、编辑或播放它们。现有本地技能与工具继续负责这些操作。不要上传凭据、整个 Codex 会话目录或无关用户文件。

本地排队返回 `queued_locally`，不是送达。节点适配器须正在运行才会转交总控。任务发起者或总控检查产物后调用 `fleet_accept`，`submitted` 不能当成验收完成。适配器仅为其子进程列明的 15 个 Fleet 协作工具配置 `approval_mode=approve`，使已授权的项目内互派任务可以执行；不写入全局审批策略，也不放行其他 MCP。其他审批或本地交互请求会使任务 `blocked`，不会自动同意系统命令、连接器授权或修改安全策略。[官方 MCP 配置](https://learn.chatgpt.com/docs/extend/mcp)

任意桌面旧聊天不自动迁移。此版本只续接由 Fleet 适配器创建并登记的本地线程。消息注入正在执行的 turn 有回执；中断时不保证恰好一次注入，不确定状态会留下记录，避免自动重复指令。

## 开发 → 审查 → 修复 → 整合

`fleet_workflow` 支持最多 20 步、有稳定工作流 ID 的流程，先列前置步骤，后列依赖步骤。每一步包含角色、目标节点、提示、验收条件、技能与产物；`dependsOn` 必须引用前面的步骤。重复提交完全相同的工作流会复用任务 ID；修改内容请使用新 ID。

依赖必须被发起者验收后才释放。审查结论写清问题位置；修复任务明确引用审查任务；整合任务先取得正确提交。自动流程不自行证明代码正确。示例见 `workflow.example.json`，替换机器名、项目与提示后提交：

```powershell
& D:\CodexFleet\runtime\node.exe D:\CodexFleet\app\src\cli.mjs workflow --config D:\CodexFleet\config\node.json --file D:\my-workflow.json
& D:\CodexFleet\runtime\node.exe D:\CodexFleet\app\src\cli.mjs summary --config D:\CodexFleet\config\node.json
```

`fleet_knowledge_publish` 可把已验收任务的结论发布成带项目、键、版本、作者、时间和来源任务的记录；只有发起者或管理员能发布。`fleet_knowledge_search` 按关键词检索最新版本。记录不改变权限，也不批量同步聊天。它适合小规模项目决策，无向量数据库依赖。

## Git 交接和合并

代码项目默认创建独立 `fleet/任务ID` worktree，基于当地仓库已有的完整 `baseCommit`。未跟踪文件与未提交修改不会被复制进去；先通过明确文件产物交接或经用户授权提交。每个节点自行保留 Git 登录。共同 Git 远端已有的提交，可在各机按原权限 fetch；Fleet 不自动发布或修改主分支。

不依赖共同 Git 远端也能交接代码：执行者先提交任务改动，用 `Export-TaskCode.ps1` 生成仅含本次基线之后提交的 bundle，把 bundle 声明为任务产物。接收者下载并核对哈希，使用 `Import-TaskCode.ps1` 导入隔离引用，再运行 `Prepare-Integration.ps1` 建立独立整合 worktree 并合并候选提交。

```powershell
& D:\CodexFleet\app\scripts\Export-TaskCode.ps1 -Repository E:\repo-task -BaseCommit <完整基线哈希> -Commit <完整结果哈希> -OutFile E:\repo-task-output\change.bundle
& D:\CodexFleet\app\scripts\Import-TaskCode.ps1 -Repository E:\repo -Bundle E:\incoming\change.bundle
& D:\CodexFleet\app\scripts\Prepare-Integration.ps1 -Repository E:\repo -BaseCommit <完整基线哈希> -CandidateCommits <结果哈希1>,<结果哈希2> -WorktreePath E:\integrations\review-001
```

接收仓库须已有基线；不支持把无共同历史的仓库强行合并。整合冲突会停止并保留工作目录，由 Codex/人员在任务授权范围内修复。成功 merge 后仍需运行项目测试，按用户已有规则提交 PR 或合入主分支。

## 同账号、断线和恢复

设备 ID 独立于账号。ChatGPT 登录的账号指纹在当地根据邮箱和本总控随机盐生成，上传散列以归并共享额度组，不上传邮箱或登录文件。同账号默认最多并行 2 个任务，每节点最多 1 个；可在总控 `groupLimits` 对邀请中的组名设为 1 等值。指纹相同而组名不同，采用最严格配置。无法识别账号的模式按人工组名处理，默认共组；管理员应正确分组。

这里只限制本 Fleet 调度的并发，不读取实时剩余额度，也不能限制用户其他桌面聊天或另一套总控的任务。实际额度不足由 Codex 返回失败/阻塞，不切换账号或绕过限制。

节点 SQLite 保存待发送事件与执行结果，总控 SQLite 保存权威台账。HTTP 请求使用事件 ID 和任务 ID 去重。总控离线时不新取任务，运行中的任务可以继续，产物快照留在当地；恢复后重连并补传。已经缓存过名称的节点可离线排队；首次离线派工应提供已知目标设备 ID。

上传/下载按块续传并校验 SHA256。节点执行中崩溃会标为 `uncertain`，保留执行位，不因心跳超时自动重派，防止旧进程仍在运行时重复写入。核实旧进程和结果后，管理员可用 CLI `resolve --task ID --confirmed-stopped --note "实际核实证据"` 结束不确定尝试，再明确创建新任务。取消状态 `cancel_requested` 不等于已停止。

启动、停止、诊断使用 `Start-Fleet.ps1`、`Stop-Fleet.ps1`、`Diagnose-Fleet.ps1`。停止脚本核对 PID、路径、启动时间，只请求停止本安装的服务，不结束其他 Codex。重启后 `uncertain` 需要上述核实；已上传或已进入待发送队列的结果继续恢复。

## 备份、升级与回退

升级前停止两个已安装角色，运行 `Backup-Fleet.ps1`。备份包含 Fleet 节点凭据，目录限制为当前用户与 SYSTEM；不要作为共享安装包。安装器拒绝覆盖仍运行的服务，不删除队列或数据。0.1.0 不提供跨数据库版本自动降级；回退应在停机后恢复同一版本的 app/runtime/config/data 完整备份，并保持原安装路径，保留 Git worktree 元数据。总控迁移时旧总控必须先停止，避免同时使用两套分叉台账；更新各节点 hubUrl 到新的私网 DNS，并保留原总控数据库和令牌。

`Disable-Fleet.ps1` 停止角色并禁用其启动项，保留数据。需要移除新增 MCP 时执行 `codex mcp remove codex_fleet`；只删除新增技能前先检查同名备份。不要删除原 Codex 登录、技能、项目，或重置全部 Tailscale Serve 路由。

## 实现来源及验证边界

现成组件：本机 Codex App Server、Node.js 内置 SQLite、Git、Tailscale 私网与 Serve。自研部分：总控台账/权限/事件回执、Windows 节点适配器、本地持久队列、MCP、协作技能、工作流与项目决策索引、安装和 Git 交接脚本。借鉴 Ruflo 的角色流程、依赖验收、来源明确的项目经验和可观察性；未安装 Ruflo 依赖、未复制其源码、未运行第二套调度器。

交付根目录的验证报告列出本次实测证据。本机多进程不能证明真实异地网络、多实体机不同账号、桌面浏览器/录屏技能或断电恢复全部可用。首次真实验收按 `跨机验收清单.md` 操作，遇到权限、网络或执行问题保留原任务与诊断记录，不宣称已成功。
