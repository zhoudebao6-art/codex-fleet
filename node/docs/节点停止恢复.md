# 节点停止超时恢复（0.3.10）

适用于既有 Fleet 节点在升级时停止超时，网站显示离线，但 service.json 对应的旧节点仍存在。无需重装或重新邀请。

1. 在故障电脑下载完整 Windows 安装包并校验发布的 SHA256。将包解压到 D:\codex+\temp 下一个新目录。
2. 从新解压包运行 scripts\Repair-FleetNode.ps1 -InstallDir D:\CodexFleet。安装位置不同时使用真实原目录。可加 -ExpectedNodeId 防止选错电脑。
3. 恢复程序获取升级锁、检查停止请求已超过 180 秒、暂停新任务，两次核验本地和网站没有在途工作，并在 D:\codex+\backups 留存私有备份。只有核实进程路径、启动参数、创建时间及 PID 均一致，才结束卡住的空闲 Fleet 节点。不会结束 Codex 桌面、其他 Node 服务或进程树。
4. 从新包运行 scripts\Update-Fleet.ps1 -PackagePath <完整ZIP路径> -Sha256 <发布哈希> -ExpectedVersion 0.3.10 -InstallDir D:\CodexFleet -Queue。查看 data\node\upgrade-status.json 并确认网站收到 0.3.10 新鲜心跳。
5. 桌面联动启动修复包含在同一包内；正常退出原 Codex 后使用“Codex Fleet 联动”。验证一个网站短任务在 Codex 桌面实际出现，再停止任务。后台在线不代表桌面已显示。

恢复证据：data\node\idle-recovery-status.json（核验和备份）、data\node\shutdown-status.json（新版退出阶段）、data\node\upgrades\recovery-*.json.result.json（升级守护）、desktop-bridge\launch-status.json（桌面启动）。

出现未结束任务、传输、待发送事件、网络不可达或身份不符时，恢复程序会保留进程及数据。先核对具体阻塞项，不要重复强制重装。诊断只分享状态及错误，不分享配置全文、邀请、令牌或 Codex 登录文件。
