# 0.3.12 桌面联动接入

桌面与 Fleet 共用一个 Codex app-server，让网站派发的同一任务出现在 Codex 桌面。0.3.12 按当前用户安装的应用清单识别入口，并为完整信任应用包直接启动被拒绝的情况提供兼容启动。每台新电脑仍须完成一次真实桌面可见与停止验收，不能把节点在线当成桌面已显示。

## 已接入电脑原地升级

使用原 Windows 用户。核对完整 windows-x64 ZIP 的发布 SHA256，解压到 `D:\codex+\temp` 的独立目录。不要运行 Setup，不需要新邀请，不要复制别的电脑的配置。先确认没有正在执行的 Fleet 任务或传输。

从新解压包运行其 `scripts\Update-Fleet.ps1`，传 `-PackagePath`、`-Sha256`、`-ExpectedVersion 0.3.12`、`-InstallDir D:\CodexFleet`，不要使用旧安装器里的升级脚本。升级器校验文件清单、等待空闲并备份，保留节点身份、登录、技能、项目映射和数据；已有安装位置不同时使用实际原目录。

新装默认已准备联动入口，检查 desktop-bridge/preparation-status.json。旧节点升级后若入口尚未准备，在没有运行中的 Fleet 工作、并且未使用共享执行器时执行：

```powershell
& 'D:\CodexFleet\app\scripts\Prepare-DesktopBridge.ps1' -InstallDir 'D:\CodexFleet'
```

这会生成桌面“Codex Fleet 联动”入口，并验证 CLI 转发。首次切换需要结束当前工作，正常退出全部 Codex 窗口，再双击新入口。不要强杀 Codex。启动入口确认共享执行器持续就绪后，才会备份并切换 Fleet 配置。入口采用进程内 CODEX_CLI_PATH，原快捷方式、全局环境、登录、技能和 Codex 数据库均保留。

启动失败时检查 desktop-bridge/launch-status.json，查看失败阶段、错误和节点恢复结果。启动器仅在共享执行器持续就绪后切换配置；切换失败恢复原配置并检查原节点启动，不强杀 Codex、不修改 WindowsApps ACL 或系统环境。应用仍在运行时需先正常退出，不能通过删除锁文件绕过。

启动后让本机 Codex 检查 `fleet_local`、`fleet_nodes`：节点在线、版本 0.3.12、`execution=desktop-shared-app-server`，并确认 Codex ready。只报告脱敏状态；不要读取或发送 desktop-bridge/runtime.json 内的本机通信令牌。

## 试装验收

由总控派一个短测试，确认同一任务出现在这台电脑的 Codex 桌面，并能看到任务正在执行；随后从网页取消并确认桌面停止、网页已取消。打开链接成功、后台有线程 ID 或版本升级成功均不算桌面显示通过。

共享模式要求 Codex 桌面保持运行。关闭桌面后执行器会不可用；Fleet 不会暗中另起后台执行器。若运行中断连，系统标记执行状态待核实，保留会话，避免自动重复发送。实际恢复需先核对原会话，不能仅将网页状态改成已停止。

## 回退

没有正在执行的 Fleet 任务、状态待核实任务或传输时，先正常退出 Codex，再运行：

```powershell
& 'D:\CodexFleet\app\scripts\Start-FleetDesktop.ps1' -InstallDir 'D:\CodexFleet' -RestoreBackground
```

然后从原 Codex 快捷方式启动。Fleet 节点身份和历史不变，回到原后台执行方式。若空闲检查阻止切换，先核实在途任务，不能删除锁文件或修改会话数据库绕过检查。配置备份保存在本机受保护的 desktop-bridge 文件夹，勿向其他设备复制。

0.3.12 直接启动采用保留原始 Win32 错误码的调用，避免 Windows PowerShell 5.1 吞掉错误码 5 后漏过应用包兼容启动。节点心跳同时上报脱敏的 desktopLaunch 阶段及错误摘要；不上传启动请求或本机通信令牌。
