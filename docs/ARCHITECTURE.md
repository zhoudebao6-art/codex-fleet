# 如何达成多机联动

## 1. 控制面与执行环境分离

总控保存设备、分组权限、任务、消息、文件索引和技能负责人。节点保留本机执行环境。任务包含目标设备、项目、批次编号、输入文件及原会话绑定；不能把一台电脑的绝对路径当成另一台电脑的路径。

`handler.mjs` 接收请求，`tasks.mjs` 负责任务状态，节点通过 `client.mjs` / `worker.mjs` 获取可执行工作。本地状态落盘，总控暂时不可达不应丢失已完成结果。网页呈现最近事件和执行状态，不能仅用最近消息时间推断“正在运行”。

## 2. 账号、设备和会话三个身份

设备节点 ID 用于联网授权，Codex 账号用于本机推理，threadId 用于接续原上下文。切换 Codex 账号不应重建 Fleet 设备身份，但需要重新验证本机执行器就绪与原会话可访问性。登录凭据不经 Fleet 在电脑间复制。

节点注册：邀请 → 本地独立身份 → 总控登记 → 心跳。每台电脑用独立邀请，不复制其他电脑的 config 或数据库。权限由用户角色、设备分组和项目映射共同限制。

## 3. 按批次派给原技能总控

绑定技能的主负责设备及原 threadId。制作请求选择可用设备，发送输入材料、输出要求和批次号。节点执行 `native-continuation` 或桌面共享会话调用；同一总控自己决定案件拆分和并发。

技能改进请求直接转给主负责总控，不再由协作层重建一套代理树。技能升级应避开正在运行的版本，远端版本不一致时核对；避免每个案件重复全量检查。

原对话续接必须带原 threadId；新建工作则创建新 thread。桌面显示需要额外的共享执行器连接及窗口验证，CLI 生成了会话不代表桌面已经呈现。

## 4. 文件传输与汇总

输入文件生成 SHA256 与大小，先登记、再按偏移上传；恢复时复用传输标识。下载端校验完整性后提供本地可读路径。输出回传保留批次、来源电脑、相对路径和校验值，汇总层收集实际文件，不自行冒充内容审核。

超时是结果未知，不等于失败可重发。先查询原任务、原传输与 outbox，再决定续传。取消请求要等待本地确认，不能直接把正在写文件的任务改为完成。

## 5. 断线、升级与防休眠

网络断开采用持久发件箱与重试，重新联网继续发送。升级前核对活跃任务和传输，正常退出、替换程序、恢复服务；失败保留日志及原身份。不要强杀未知 Codex 会话或清空数据库解决卡住。

电源代理只处理授权范围内的电源请求。Wake-on-LAN 需要网卡、固件、供电和同网段发送条件；异地通常由在线同网段节点发包。Windows 注销、锁屏、休眠对 CLI 和桌面录屏等技能的影响不同，需分别验收。

## 6. 发布者经验

有效链路是“材料交接 → 原总控制作 → 文件回传 → 汇总”。应减少重复预检、重复任务、每件案件多层代理和无条件维护循环。生产任务与维护任务分开，停用节点不得自动重新入选。

不能承诺无条件无人值守：审批、登录失效、磁盘耗尽、桌面连接不兼容等要明确呈现原因，保留现场并阻止重复执行。先让恢复有状态、有证据，再逐步减少人工环节。
